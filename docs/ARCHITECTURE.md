# Nevinnomyssk 3D: architecture and module contracts

This is a real-time 3D recreation of Nevinnomyssk (Невинномысск, Stavropol Krai) that runs in the browser. It's built with three.js r186, WebGL2, TypeScript and Vite. The Python pipeline in `pipeline/` turns open geodata into compact web assets in `public/data/`. The app streams those assets and builds the city in the browser.

## Data sources (all open, all fetched by `pipeline/`)

| Source | What | Script |
|---|---|---|
| Overture Maps 2026-09-23 (S3) | buildings (OSM + Microsoft ML footprints), roads/rail segments, water, land use, land cover, infrastructure (power towers/lines, bridges, barriers, bus stops...), places (POIs), admin boundaries | `pipeline/overture_fetch.py <theme> <type>` → `data/raw/<theme>_<type>.parquet` |
| Copernicus GLO-30 DSM (S3) | 30 m elevation → `data/processed/dem_raw.npy`, bare-earth approximation `dem_ground.npy`, `dsm_excess.npy` (surface minus ground, a building/tree height signal) | `pipeline/dem_fetch.py` |
| Sentinel-2 L2A, tile 37TGK (S3) | cloud-free summer median composite at 10 m: `s2_rgb.npy` (linear reflectance), `s2_nir.npy`, `s2_ndvi.npy` | `pipeline/s2_composite.py` |
| ESA WorldCover 2021 (S3) | 10 m land-cover classes `worldcover.npy` | `pipeline/worldcover_fetch.py` |

Street-level imagery (Yandex Panoramas, Mapillary) can't be used: this build environment's network policy blocks those hosts. Facade and material choices come from typical regional architecture plus research with the WebSearch tool.

`data/raw/*.parquet` are committed. `data/processed/` is git-ignored and regenerated by the scripts. Every `.npy` raster is a north-up grid covering the region, where row 0 is the north edge.

## World frame (important)

- The projection is transverse Mercator centred on **lon 41.94, lat 44.64** (`pipeline/config.py`, `src/core/geo.ts`).
- In the **three.js world**, X points east and Z points south (Z = −north). Y is height in metres above sea level, and the terrain sits at roughly 280–700 m.
- In the pipeline, 2D coordinates are `(x=east, y=north)`. To convert to world coordinates, use `z = -y`.
- The detailed region is a 20 480 m square centred on the origin, so x and z range over [−10240, 10240]. Rasters use 10 m texels (2048²). The heightmap has 2049² samples at 10 m and is vertex-centred: sample `(i, j)` sits at `x = −10240 + 10 i`, `z = −10240 + 10 j`.
- Headings are measured in degrees clockwise from north. Pitch is in degrees, and negative pitch looks down.
- Useful places (world x, z): Eternal Flame (182, 64), city park (−317, 130), Kino Mir (−29, 174), Stadium Khimik (−604, 422), railway station (1875, 1049), Pokrovsky cathedral (1435, 2710), Serafim Sarovsky church (601, −116), Nevinnomysskaya GRES (≈ −844, −2167), Azot works (north, around (0…1500, −1500…−4000)), bus station (1330, −163). Kochubeevskoye village lies at the west edge (x ≈ −9000).

## Runtime architecture

```
index.html → src/main.ts
  Settings (URL params, quality tier)
  AppContext (src/core/context.ts)
    renderer (WebGL2, sRGB output, AgX tone mapping, shadow maps on)
    scene + camera (main world, near plane adapts to altitude, far 80 km)
    backdrop.scene + backdrop.camera (sky dome, far terrain/Caucasus; rendered first with its own depth range)
    heightfield (src/core/heightfield.ts)  ← ALWAYS sample ground height through this
    env (src/core/env.ts): time of day, sun direction (real solar position), night factor, wind, weather
    input + controllers (fly built in; walk/drive registered by physics)
    service registry: ctx.provide(name, api) / ctx.get(name) / await ctx.need(name)
    registries: registerMaterial, registerColliders, registerController, onUpdate
    render pipeline (replaceable): BasicPipeline by default; sky module installs post-processing; pathtracer swaps its own in
  modules (src/modules/<id>/index.ts), loaded in parallel via dynamic import
```

### Module contract

```ts
const mod: CityModule = {
  id: 'water',
  after: ['terrain'],          // optional: init after these (if loaded)
  async init(ctx) { ... },     // build meshes, register services; await long work or wrap it in ctx.pending(p)
  update(dt, ctx) { ... },     // optional per-frame hook
};
export default mod;
```

- Keep a module **self-contained** inside `src/modules/<id>/`. You can add as many files as you like there, plus `src/workers/<id>*.ts` if you need workers. Don't edit another module's files.
- **Don't edit** `src/core/*`, `src/main.ts`, `index.html`, `package.json` or `tools/shot.mjs`. If you need a core change, describe it in your final report. Small additive helpers can go in your own module.
- Treat other modules' services as optional. Use `ctx.get('x')`, which returns undefined if the module is missing, or `await ctx.need('x')`, which waits and never rejects but may never resolve. Degrade gracefully if a service is absent, so that `?only=<your module>` still works.
- Initial streaming that matters for a screenshot must go through `ctx.pending(promise)`. That keeps `window.__city.isReady()` false until the work finishes.
- Every frame, read `ctx.settings.profile` for quality-dependent parameters. Also react to `ctx.events.on('settings', …)`.

### Materials, lighting, shadows

- Prefer `MeshStandardMaterial` or `MeshPhysicalMaterial`, customised with `onBeforeCompile` or `customProgramCacheKey` when you need procedural detail. That keeps lights, shadows, fog, the path tracer and CSM working.
- Pass every material through `ctx.registerMaterial(mat)`. The sky module owns sun and sky lighting plus cascaded shadow maps, and patches registered materials, for example with `csm.setupMaterial`.
- If you really need a raw `ShaderMaterial` (water, sky, grass), include three's fog chunks. Use `ctx.env.sunDirection`, `ctx.env.sunColor` and `ctx.env.sunIntensity` for lighting consistency.
- Set `castShadow` and `receiveShadow` sensibly. Terrain receives shadows. Buildings, trees and landmarks both cast and receive them.
- For the **path tracer**, meshes use their standard material. Set `object.userData.noPathTrace = true` to exclude an object, such as grass, particles or helper geometry. Set `object.userData.ptMaterial = <MeshPhysicalMaterial>` to supply a proxy material when the real one is a custom shader. Water is an example: it should use a transmissive or reflective physical proxy.
- Night: `ctx.env.night` goes from 0 (day) to 1 (night). Windows, street lights and vehicles should glow using emissive terms scaled by it.

### Services (names and expected APIs)

Each module that implements a service must provide at least the following. It may add more.

| service | provider | API |
|---|---|---|
| `terrain` | terrain | `{ heightAt(x,z): number, normalAt(x,z,out?), groundTypeAt(x,z): string, mesh?: Object3D }` |
| `water` | water | `{ isWater(x,z): boolean, levelAt(x,z): number \| null }` |
| `buildings` | buildings | `{ hideById(ids: string[]), hideInPolygon(ringXZ: number[]), infoAt(x,z): {id, name?, levels, height, cls} \| null, count }` |
| `roads` | roads | `{ graph: { nodes: Float32Array /*x,z*/, edges: Array<{a,b,cls,width,oneway,name?,points:Float32Array}> }, nearest(x,z): {x,z,dirX,dirZ,width,cls,name?} \| null, streetNames(): string[] }` |
| `vegetation` | vegetation | `{ clearInPolygon(ringXZ: number[]) }` |
| `sky` | sky | `{ sunLight: DirectionalLight, setTime(h), setWeather({cloudCover, rain, fog}) }` |
| `physics` | physics | `{ RAPIER, world, raycast(origin, dir, maxDist), spawnBall(pos, vel) }` plus `walk` and `drive` controllers registered on ctx |
| `pathtracer` | pathtracer | `{ start(), stop(), active: boolean, samples: number }` |
| `ui` | ui | `{ toast(msg), registerPanel(...) }` |
| `places` | ui | `{ list: Array<{name, x, z, kind}>, flyTo(name) }` |

### Events

`ready` (all modules initialised), `frame`, `resize`, `controller` (mode changed), `settings` (quality changed), `time` (time of day changed from the UI), `teleport` ({x,z}), `material:added`, `colliders:added`, `service:<name>`.

### Physics colliders

`ctx.registerColliders({ id, query(x, z, r) })` returns stable-keyed `StaticCollider` shapes (box, prism, trimesh or cylinder) near a point. The physics module streams them in and out around the player. Buildings provide prisms made from footprints, trees provide cylinders, and landmarks provide boxes or trimeshes. Terrain is handled by physics directly through `ctx.heightfield`.

## Data contracts (public/data)

- `manifest.json` holds the origin, projection, region and terrain descriptor, and is written by `pipeline/build_terrain_base.py`. The terrain module may rewrite the terrain files, but has to keep the manifest keys.
- `terrain/height.bin.gz` is a uint16 LE grid of 2049², row 0 at the north edge, where `h = hMin + v*hScale`. Load it through `HeightField` only.
- `terrain/ortho.jpg` is the 2048² Sentinel-2 composite, stored as sRGB-encoded linear reflectance (so it's usable directly as albedo).
- `terrain/landcover.png` holds 2048² WorldCover codes (10 tree, 20 shrub, 30 grass, 40 crop, 50 built, 60 bare, 80 water, 90 wetland).
- Each module writes its own files to `public/data/<module>/`, using `pipeline/build_<module>.py`, and documents its format at the top of that script. Binary files should be little-endian typed arrays, gzipped (`.bin.gz`), and loaded with `fetchBuffer()`.
- The whole pipeline is re-run with `python3 pipeline/build_all.py`, which runs `build_<module>.py` scripts in dependency order. Register your script there.
- Keep the total size of `public/data` reasonable. Aim for under 60 MB for everything, and quantise coordinates, for example to int16 decimetres relative to a tile origin.

## Testing / visual verification

```
node tools/shot.mjs --preset overview,center_street --dir tools/shots/<you>      # named views from tools/views.json
node tools/shot.mjs --cam x,y,z,heading,pitch --time 19 --only terrain,sky,water --out tools/shots/<you>/a.png
```

The harness starts a Vite dev server, renders headlessly with SwiftShader (slow, but correct WebGL2), waits for `__city.isReady()`, prints module status and browser console errors, and saves a PNG. Open the PNG with the Read tool to look at it. Default quality for shots is `medium`. Use `--quality high` to test the full effects. Budget roughly 20–90 s per run.

`npx tsc --noEmit` must stay clean for your files.

## Performance budget (desktop, quality=high, mid-range GPU)

- Target 60 fps at 1080p. There should be no single frame hitch above 100 ms after load.
- Budgets: draw calls < 1500, triangles < 6 M.
- Stream and LOD everything. Use InstancedMesh or BatchedMesh, merge per-tile geometry, and cull with frustum and distance checks.
- Heavy CPU generation (meshing ~58k buildings, roads) runs in Web Workers (`new Worker(new URL('./x.worker.ts', import.meta.url), {type:'module'})`), or incrementally across frames.
